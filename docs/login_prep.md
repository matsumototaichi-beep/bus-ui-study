## 0. 何がいちばん危ないか

| | |
|---|---|
| **パスワードを忘れると戻せない** | メールアドレスを使わない方式（`uiStudy-0.8.0` 以降）なので、Supabase から再設定メールを送れない。宛先が `@id.local` という実在しないドメインだから、永久に届かない |
| **参加者は別の日にもう一度ログインする** | 1人2回。1回目と2回目は1週間以上空くことがある |
| **2回目は端末に残っていない可能性が高い** | Safari には、7日間そのサイトを訪れないと保存データを消す仕様がある。ログイン状態も消える |

> **だから、アカウントは事前にこちらで作り、IDとパスワードを刷ったカードを渡す。**
> （2026-09-26 松本の判断。当日その場で各自に決めてもらう方式から変更した）

## 1. 事前に作るアカウント

ID は `A` 〜 `X` の24人。**A〜L が本番、M〜X は予備。** 予備は、抜けた人と同じ組から使う。

| | ID | 予備 |
|---|---|---|
| 奇数組 | A C E G I K | M O Q S U W |
| 偶数組 | B D F H J L | N P R T V X |

条件はアプリが QR の回・ゆき／かえり・アカウントの組から決める（`HANDOFF.md` §8 #41）。

## 2. 作り方（実験の前日まで）

```bash
python tools/create_accounts.py
```

事前に Supabase の service_role キーを環境変数で渡す（PowerShell）:

```bash
$env:SUPABASE_SERVICE_ROLE_KEY = "<Supabase ダッシュボード → Settings → API → service_role>"
```

刷り上がりだけ先に見たいときは `--dry-run`（Supabase には触らないが、`★UI研究/accounts.csv` は上書きされる）:

```bash
python tools/create_accounts.py --dry-run
```

出来るもの（どちらも `★UI研究` に出る）:

| ファイル | 中身 |
|---|---|
| `accounts.csv` | 名前・ID・パスワードの対応表（松本の手元用） |
| `accounts_cards.html` | A4に8面で刷る配布カード。ブラウザで開いて印刷 |

> ### ⚠️ この2つはリポジトリに入れない
> **このリポジトリは public。** リポジトリの外（`★UI研究`）に出しているので通常は入らないが、
> コピーして持ち込まないこと。
> **service_role キーは全権限を持つ。** 画面共有・スクショ・コミットに出さない。
> 環境変数で渡すだけにして、ファイルには書かない。

パスワードは紛らわしい字（`i` `l` `1` `o` `0`）を抜いた英数字8文字で自動生成する。
カードを見ながらスマホで打つため。

## 5. QRポスター（3枚）

土台は `https://matsumototaichi-beep.github.io/bus-ui-study/`

| ポスター | 付けるパラメータ |
|---|---|
| **1回目** | `?round=1` |
| **2回目** | `?round=2` |
| **計数研究** | `?study=count` |

**ポスターには条件の中身を書いていません。** 右上の「1回目」「2回目」「計数研究」だけで見分けます。
参加者に条件の存在を気づかれると、条件そのものへの反応（要求特性）が入るためです。

`?input=` / `?unknown=` はテスト用。参加者には使わない。

## 6. つまずいたときの早見表

| 画面に出るもの | 原因 | その場の対処 |
|---|---|---|
| **IDまたはパスワードが違います** | 打ち間違い | **「パスワードを表示して確かめる」にチェック**を入れて、カードと見比べる |
| | 「新規登録」タブのまま押した | **「ログイン」タブ**に切り替える |
| **IDは半角英数・ハイフン・アンダースコアで20文字までにしてください** | 全角で入力 | `uiStudy-0.8.1` が自動で半角に直す。それでも出るなら、入力欄を一度タップして外す |
| **パスワードは6文字以上にしてください** | 途中までしか入っていない | カードのとおり8文字入れる |
| **登録はできましたが、サーバー側でメール確認が必要な設定のままです** | Confirm email が ON に戻っている | 松本が Supabase で即 OFF にする。前日チェック（§3）で潰しておく |
| 画面が古い・ボタンの有無が想定と違う | GitHub Pages のキャッシュ（約10分） | URLの末尾に `&cb=1` を足して開き直す |
| 通信が繋がらない | 駅前の電波 | **回答はいったん端末に貯まる。** 電波が戻ったとき自動で送られるので、そのまま続けてよい |
| パスワードを無くした | カード紛失 | 松本が `accounts.csv` を見て伝える。CSVも無ければ `--force` で作り直す |

## 7. ブラウザの注意（参加者への説明に入れる）

- **QRはカメラアプリから読んで、いつものブラウザ（Safari／Chrome）で開く。**
  LINE や Discord のアプリ内ブラウザで開くと、保存場所が別になり、
  2回目に開き直したときログインが切れている
- **2回目も同じ端末・同じブラウザで開く**
- 乗車中に**ログアウトしない**（`uiStudy-0.8.1` で確認ダイアログを入れたが、念のため説明で触れる）

## 8. アプリ側でやった手当て（`uiStudy-0.8.1`・2026-09-26）

| | なぜ |
|---|---|
| 全角で打たれたIDを半角に直す | スマホのキーボードが日本語入力のままだと「ｔａｒｏ０１」と入り、書式エラーで止まる。バス停で直し方を説明する時間はない |
| パスワードを表示できるようにした | 伏せ字のままだと打ち間違いに気づけない。2日目の再ログインで効く |
| ログアウトに確認を入れた | 乗車中の誤タップで落ちると、電波の悪い車内で再ログインする羽目になり、その便の回答が丸ごと飛ぶ |
| 登録画面の注意書きを「別の日にもう一度使います」に直した | 2日構成になったため |

**10月上旬でアプリの改修は凍結する。** 実験の途中で版が変わると条件が揃わない。
