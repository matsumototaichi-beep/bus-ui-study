## 0. 何がいちばん危ないか

| | |
|---|---|
| **パスワードを忘れると戻せない** | メールアドレスを使わない方式（`uiStudy-0.8.0` 以降）なので、Supabase から再設定メールを送れない。宛先が `@id.local` という実在しないドメインだから、永久に届かない |
| **参加者は別の日にもう一度ログインする** | 1人4乗車＝2日構成（`operation_plan.md` §2.5）。1日目と2日目は1週間以上空くことがある |
| **2日目は端末に残っていない可能性が高い** | Safari には、7日間そのサイトを訪れないと保存データを消す仕様がある。ログイン状態も消える |

> **だから、アカウントは事前にこちらで作り、IDとパスワードを刷ったカードを渡す。**
> （2026-09-26 松本の判断。当日その場で各自に決めてもらう方式から変更した）

## 1. 事前に作るアカウント

`p01` 〜 `p24`。**3名で1組、組ごとに群を交互に置く。** 実際に使うのは組1〜組4（12名）、残りは予備。

| 番号 | 組 | 群 | 掲げるQRポスター（昼1／昼2／夕1／夕2） | アンケート版 |
|---|---|---|---|---|
| p01・p02・p03 | 組1 | **群1** | **A ／ B ／ D ／ C** | v1・v2・v3 |
| p04・p05・p06 | 組2 | **群2** | **D ／ C ／ A ／ B** | v4・v1・v2 |
| p07・p08・p09 | 組3 | **群1** | 群1と同じ | v3・v4・v1 |
| p10・p11・p12 | 組4 | **群2** | 群2と同じ | v2・v3・v4 |

**入力方式は実施日ごとに固定**（2026-09-26 変更）。群1は昼＝ステッパー／夕方＝テンキー、群2はその逆。
「わからない」ボタンの有無は便ごとに変わる。

- 群1が6名・群2が6名で釣り合う。アンケートも v1〜v4 が3名ずつで釣り合う
- **どちらの群の人も、4乗車で「ボタンあり×空いている／あり×混んでいる／なし×空いている／なし×混んでいる」を1回ずつ経験する。** 要因Bと要因Cが完全に被験者内で交差する
- **入力方式も、4乗車で「2方式 × ボタン2通り」の4組み合わせを1回ずつ経験する。** 組で昼夕を入れ替えてあるので、全体としてはどちらの方式も空いている便・混んでいる便の両方に現れる
- **同じ便に乗る3名は必ず同じ組＝同じ群にする。** 群を混ぜると、同じバスの中でボタンが出る人と出ない人が並び、参加者に条件の存在を気づかれる（要求特性）
- **カードは番号順に3枚ずつ渡す。** 順番を崩すと群とアンケート版の釣り合いが崩れる

## 2. 作り方（実験の前日まで）

```bash
python tools/create_accounts.py
```

事前に Supabase の service_role キーを環境変数で渡す（PowerShell）:

```bash
$env:SUPABASE_SERVICE_ROLE_KEY = "<Supabase ダッシュボード → Settings → API → service_role>"
```

刷り上がりだけ先に見たいときは `--dry-run`（Supabase には一切触らない）:

```bash
python tools/create_accounts.py --dry-run
```

出来るもの:

| ファイル | 中身 |
|---|---|
| `accounts.csv` | 番号・組・群・アンケート版・ID・パスワードの対応表（松本の手元用） |
| `accounts_cards.html` | A4に8面で刷る配布カード。QR付き。ブラウザで開いて印刷 |

> ### ⚠️ この2つは絶対に commit しない
> **このリポジトリは public。** `.gitignore` に `accounts*.csv` / `accounts*.html` を入れてあるので
> 通常は入らないが、`git add -f` は使わないこと。
> **service_role キーは全権限を持つ。** 画面共有・スクショ・コミットに出さない。
> 環境変数で渡すだけにして、ファイルには書かない。

パスワードは紛らわしい字（`i` `l` `1` `o` `0`）を抜いた英数字8文字で自動生成する。
カードを見ながらスマホで打つため。

> ### ⚠️ 乗車時は必ずポスターのQRを読ませる
> **カードに刷ってあるQRはパラメータの付かない素のURL**で、条件が何も付きません。
> カードのQRから入ると入力方式もボタンの有無も指定されず、**その便のデータが条件不明になります。**
> カードのQRは「アプリの場所を控えておく」ためのもので、乗車時には使いません。

## 5. 配布URL（QRポスターにする2つ）

土台は `https://matsumototaichi-beep.github.io/bus-ui-study/`

| ポスター | 条件 | 付けるパラメータ |
|---|---|---|
| **A** | ステッパー ＋ ボタンあり | `?input=stepper` |
| **B** | ステッパー ＋ ボタンなし | `?input=stepper&unknown=off` |
| **C** | テンキー ＋ ボタンあり | `?input=numpad` |
| **D** | テンキー ＋ ボタンなし | `?input=numpad&unknown=off` |

**ポスターには条件の中身を書いていません。** 右上の `A` `B` `C` `D` だけで見分けます。
参加者に条件の存在を気づかれると、条件そのものへの反応（要求特性）が入るためです。

**4枚とも持っていき、その日に使うのは2枚だけ**（その日の入力方式のぶん）。

## 6. つまずいたときの早見表

| 画面に出るもの | 原因 | その場の対処 |
|---|---|---|
| **IDまたはパスワードが違います** | 打ち間違い | **「パスワードを表示して確かめる」にチェック**を入れて、カードと見比べる |
| | 「新規登録」タブのまま押した | **「ログイン」タブ**に切り替える |
| **IDは半角英数・ハイフン・アンダースコアで3〜20文字にしてください** | 全角で入力 | `uiStudy-0.8.1` が自動で半角に直す。それでも出るなら、入力欄を一度タップして外す |
| **パスワードは6文字以上にしてください** | 途中までしか入っていない | カードのとおり8文字入れる |
| **登録はできましたが、サーバー側でメール確認が必要な設定のままです** | Confirm email が ON に戻っている | 松本が Supabase で即 OFF にする。前日チェック（§3）で潰しておく |
| 画面が古い・ボタンの有無が想定と違う | GitHub Pages のキャッシュ（約10分） | URLの末尾に `&cb=1` を足して開き直す |
| 通信が繋がらない | 駅前の電波 | **回答はいったん端末に貯まる。** 電波が戻ったとき自動で送られるので、そのまま続けてよい |
| パスワードを無くした | カード紛失 | 松本が `accounts.csv` を見て伝える。CSVも無ければ `--force` で作り直す |

## 7. ブラウザの注意（参加者への説明に入れる）

- **QRはカメラアプリから読んで、いつものブラウザ（Safari／Chrome）で開く。**
  LINE や Discord のアプリ内ブラウザで開くと、保存場所が別になり、
  2日目に開き直したときログインが切れている
- **2日目も同じ端末・同じブラウザで開く**
- 乗車中に**ログアウトしない**（`uiStudy-0.8.1` で確認ダイアログを入れたが、念のため説明で触れる）

> 条件のローテーション（テンキー／ステッパーの交互出し）の位置は端末に保存されるが、
> **消えても釣り合いは崩れない。** 1便8回答のうち4回答ずつになるのは、どこから始めても同じ。
