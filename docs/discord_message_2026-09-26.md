教授からの「**こことここでアプリを比較したい、みたいなのを簡潔にまとめて Discord のチャットで送ろう**」への回答。
**下のコードブロックの中がそのまま送信本文**（約1,000字。Discord の2,000字制限に収まる）。

```
【卒研】アプリで何と何を比べたいか

■ 前提
同じ路線・同じ区間（ＪＲ吹田駅（北口）⇔桃山台駅・18停留所・片道35分）で、時間帯だけを変えて「混んでいない便」と「混んでいる便」を作ります。路線・停留所・所要時間・運賃が全部そろうので、混雑以外の差が入りません。

■ 比べたいのは3組です

① テンキー ⇔ ステッパー（人数の入れ方）
どちらが速く、操作が少なく、正確に答えられるか。同じ人の同じ便の中で、アプリが自動で交互に出します。

② 「わからない」ボタン あり ⇔ なし
逃げ道があると人数の欠損が増えるのか。便ごとに配布URLで固定します（画面の中で出たり消えたりすると参加者に気づかれるため）。

③ 混んでいない便 ⇔ 混んでいる便
①②の差が混雑で変わるのか。そして人数が答えられなくなっても、6段階のクラスは答え続けられるのか。

■ ③が本題です
9/18の先行実験で、14〜20人の便は終点で人数がぴったり0に閉じたのに、39人の便では最大10人ずれました。移動中のバスで正確な人数が測れないことは分かったので、そのうえで「混んでいるかどうかは取れるのか」「人数の代わりになる指標は何か」を見ます。第一候補は既存の6段階クラスです（1タップなので混雑時も欠損しにくい）。ほかに、回答にかかった時間・「わからない」率・同じ便の回答のばらつき・5や10への丸め率・押し直しの回数を、アプリのログからすでに全部取っています。

■ 乗車回数
1人あたり4回（混んでいない日に往復2回、混んでいる日に往復2回）。3人×4組＝12名なので、実施8日・16便です。計数役2名が全便に乗るので、延べ80乗車になります。昼と夕方で別の人になる場合は、1人2回・4日・8便・延べ40乗車まで下がります。

■ 謝礼・実費
謝礼金は出しません。バス運賃（1乗車220〜240円）だけ実費で持ちます。延べ80乗車で約1.8〜2.0万円です。大学⇔吹田駅は徒歩なので0円です。

■ アプリ
今の版（uiStudy-0.8.0）のまま出せます。必要なログが全部取れていることを実機で確認しました。ID＋パスワードだけで登録でき、メールアドレスは要りません。10月上旬で改修を凍結します。
```
