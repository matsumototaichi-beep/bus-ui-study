# 分析の準備（アンケートとアプリの記録をつなぐ）

実験のあと、アンケートの答えとアプリの記録を1つの表にする手順です。
道具は `tools/join_survey_app.py`、決まり（どの行を使うか・問題の印）は `UI_STUDY_SPEC.md` §8 にあります。

書き出したファイルは個人に関わるので、`exports/<日付>/`（git に入らない）かリポジトリの外に置きます。

## 1. アンケート（スプレッドシートの4シート）

1. スプレッドシート「UI研究 アンケート回答」を開く（URL は `../★UI研究/アンケートURL.xlsx`）
2. 下のタブで「1回目_桃山台」を選び、「ファイル → ダウンロード → カンマ区切り形式（.csv）」で保存する。ほかの3シートも同じ
3. 4つの CSV を1つのフォルダ（例 `exports/2026-10-20/forms/`）に入れる。ファイル名は「UI研究 アンケート回答 - 1回目_桃山台.csv」のままでよい
4. スプレッドシートで2つ確かめる
   - 1行目の見出しが、今のフォームの問（`docs/questionnaire/フォームの中身_2026-10-11.md`）と合っているか。あとから足した問の列は右の端に付き、消した問の列は残る。道具は「問N」と問の文で列を探し、合わない列は「列の確かめ」に出す
   - 時間帯が東京か（「ファイル → 設定」）

## 2. アプリの記録（Supabase）

Supabase のダッシュボードの **SQL Editor**（全件を見られる管理用の画面）で、下の3つを1つずつ流し、結果を CSV で保存します。
service_role キー（何でもできる鍵）は使わず、どこにも書きません。

```sql
-- (1) ID の対応：surveyor_id（ログインした人の番号）→ カードの ID。保存名 id対応.csv
select u.id as surveyor_id, split_part(u.email, '@', 1) as login_id
from auth.users u
order by login_id;
```

```sql
-- (2) 操作ログ。保存名 ui_sessions.csv
select * from public.ui_sessions order by created_at;
```

```sql
-- (3) 回答。保存名 ui_responses.csv
select * from public.ui_responses order by created_at;
```

全部の行が出たかを、件数で確かめます。道具が画面に出す「読んだ行」と同じになるはずです。

```sql
select (select count(*) from public.ui_sessions)  as sessions,
       (select count(*) from public.ui_responses) as responses;
```

件数が合わないとき（結果の表示に上限がある場合）は、Table Editor でそれぞれの表を開き、CSV で書き出します。
`uiStudy-0.9.6` からは、操作ログに答えた人の ID（`variant.login_id`）も入ります。道具はそちらを先に使い、無い行だけ (1) の対応で ID に直します。

## 3. つなぐ

```
python tools/join_survey_app.py --forms exports/2026-10-20/forms --sessions exports/2026-10-20/ui_sessions.csv --responses exports/2026-10-20/ui_responses.csv --idmap exports/2026-10-20/id対応.csv --ids A,B,C,D,E,F,G,H,I,J,K,L --since 2026-10-13 --out exports/2026-10-20/つないだ表
```

| 指定 | 意味 |
|---|---|
| `--ids` | 実際に参加した人の ID。予備のカードを使ったら足す。これ以外の ID に印を付ける |
| `--since` | この日より前の行（実験の前のテストなど）を読まない。読まなかった数は問題の一覧に出る |
| `--app-version` | 分析に使うアプリの版（`,` 区切り）。省くと今の `index.html` の版。実験の途中で版を上げたら、両方を書く |

出てくるもの（`--out` のフォルダ）：

- `つないだ表.xlsx`：シート「区間ごと」（参加者×回×区間ごとに1行）・「問題の一覧」・「アンケートの行」・「列の確かめ」・「読み方」（列の意味）
- 同じ中身の CSV（`区間ごと.csv`・`問題の一覧.csv`・`アンケートの行.csv`）。分析のスクリプトはこちらを読む

## 4. 見ること

1. 画面の「読んだ行」が、Supabase の件数とスプレッドシートの行数に合うか
2. 「問題の一覧」を上から見る。**道具は行を消さない。**
   - 重さ「外す」：道具が外す案を付けたもの（確認用アカウント、乗る前に答えた南口のアンケート、記録のないアンケートなど）
   - 「要確認」：人が見て決めるもの。「扱いの案」に、どう決めるかの案がある
   - 「記録のみ」：知らせるだけ
3. 決めたこと（どの行を、なぜ外したか・直したか）は `docs/log/` に書き残す
4. 「列の確かめ」に印があれば、スプレッドシートの1行目を見る

## 5. 道具の確かめ

```
python tools/test_join_survey_app.py --out <リポジトリの外のフォルダ>
```

偽の参加者（A・B の1回目・2回目と、切り替え忘れ・前の回のタブ・回のない記録など問題の例ごとの参加者）のデータを作って道具に通し、条件・SUS の点・問題の印が正しく出るかを確かめます。
道具を直したら流します。

## 6. フォームが変わったら

`python tools/read_forms.py` で、今のフォームと控え（`docs/questionnaire/フォームの中身_*.json`）を比べます（フォームは読むだけ）。
違っていたら `--save` で控えを作り直し、`python tools/make_questionnaire.py` で紙の予備も作り直します。
問の文から表の列名が決まらない問が出たら、道具は止まるか、その答えを「その他の答え」の列に入れて知らせます。
