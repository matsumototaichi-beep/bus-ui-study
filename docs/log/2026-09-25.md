# 2026-09-25 教授の助言で設計を組み直し（2路線 → 同一路線・時間帯で混雑水準を作る）

指導教員から実験の枠組みについて助言があり、研究の問いを3本立てに組み直した。
路線は**吹田市内線2系統のまま変えない**。混雑水準は**便の時間帯**で作る。

---

## 1. 教授の助言（要旨）

- 千里の山の上の方だと人が少ないからいいのでは
- **数えられる便をベースにした方がいい。空いている便で計測を行う実験**
- 今のままの便だとちょっと数えられないで終わっちゃうので、使う便を変えよう
- 数えられる時：どういう数え方がいいのか、アプリをどう作るとわかりやすくなるのか
- 数えられない時：どうやっても無理。**抜け道を探す。「about でもいいから数えられる」みたいな**
- 最終的に正確な人数は測れないけれど、**混んでるか混んでないかはわかります**、という位置づけにする
- 混雑時は正確な人数は数えられないが、**混雑度合いを何段階かに推定できる。その手がかりになる**
- **2パターン計測する（混んでいるときと混んでいない時）**
- 実験は3人でやりましょう（＝1便あたり参加者3名。従来どおり）

追加で「**時間をずらせば今乗っている路線でも空いている路線でいける**」との助言があり、
路線変更は行わないことになった。

## 2. 何が変わったか

### 位置づけ

> **移動中のバス車内で、正確な乗車人数を測ることはできない。**
> **しかし「混んでいるかどうか」は取れる。そして混雑時には、人数の代わりになる手がかりがある。**

旧版は「混雑時に数えられない」ことを仮説の中心（H2・H3）に据えていた。
それだと**数えられないまま終わる**。数えられる便を主戦場にし、
数えられない便では人数の代わりになる指標を探す、という2本立てにする。

### 研究の問いを3本立てに

| | 問い | 場 |
|---|---|---|
| **RQ1** | 数えられる状況で、どの回答UIが良いか | 空いている便（15時台） |
| **RQ2** | 正確な人数の代わりになる指標は何か | 混んでいる便（17時台以降） |
| **RQ3** | 空いている便で作った「指標→人数」の関係は、混んでいる便に外挿できるか | 両方 |

H1・H2 は RQ1 の下にそのまま入る。H3 は「混雑が進むほど欠損・所要時間・ばらつき・丸め率が増える」
という形に書き換え、**H4「クラスは人数と違って混雑時にも欠損せず、一致度も保たれる」**を新設した。

### 混雑度の扱いを格上げ

**統制できない交絡 → 便の時間帯で作る操作変数（要因C）** に変えた。
旧版の「統制できないので自然変動を事後に層別する準独立変数」という扱いは廃止。

先行実験（2026-09-18）の実測がそのまま2水準の根拠になる。

| 発車時刻 | 車内人数 | 数えられたか |
|---|---|---|
| 15時台（見込み） | 5〜15人 | 数えられる |
| 16時台（見込み） | 10〜22人 | 中間 |
| **17:18（実測）** | **8人 → 39人** | **崩れた**（最大10人ずれ／「正直この辺から車内人数は適当」） |

### 割り付けは「日」単位

同じ参加者に1日で両方を経験させると拘束が3時間を超えるので、**日によって集合時刻を変える**
（早い回の日／遅い回の日）。参加者には別日にもう一度来てもらい、要因Cを被験者内にする。
組めない参加者は被験者間でも可（2026-09-24 松本の判断）。

> ⚠️ **遅い回の日は、松本が17時台に集合場所にいる必要がある。** アルバイトとの兼ね合いは未確認。
> 松本は同乗しないので拘束は集合・説明・送り出しの約40分。

## 3. 人数の代わりになる指標 ― 第一候補は「クラス6段階」

松本の判断（2026-09-25）で、**まず既存の6段階クラスが指標として機能するかを検証し、
そのうえで他の手がかりを探す**方針にした。

採る理由：

- **アプリの改修が一切要らない。** 改修凍結（10月上旬）に影響しない
- クラスは**1タップで答えられるので、混雑時にも欠損しにくい**
- 「正確な人数は測れないが、混んでいるかどうかは取れる」という位置づけに最も素直に対応する

検証すべきことは `UI_STUDY_SPEC.md` §1 RQ2 に4項目で書いた。
**要になるのは「混雑時にクラスの一致度（ICC）が落ちるか」**。
人数が混雑時に崩れることは分かっているが、**クラスの一致度まで崩れるなら
「混んでいるかどうかも取れない」ことになり、本研究の位置づけそのものが成立しない。**
逆に保たれるなら「人数は無理だがクラスは取れる」と実データで言える。

H4 は反証されうる形で立ててある。棄却された場合は、回答者に聞く追加項目
（立っている人の数など）へ進む。

### 追加項目を足さなかった理由

「立っている人の数」を足す案を検討した（混むほど立ち客が増えるので欲しいところで精度が上がる、
クラス3以上なら「座席約30＋立ち客数」で総数を近似できる、という理屈）。
足さなかったのは、**項目を足すと回答負担が増え、回答率そのものが下がるため**。
回答率は本研究の従属変数なので、これは実害になる。まずは改修ゼロで始める。

### ★設計に効く指摘が2つ

**(1) 北口／南口の枠組みは2系統には当てはまらない。**
2系統は「南口〜吹田市役所前〜北口〜上山手町〜…〜桃山台駅」という一本の系統で、
北口と南口の両方に停まる。北口グループ対南口グループの比較として使うと、
それは2系統以外（北口のみ＝5・6・21／南口のみ＝3・10・12ほか）の話になる。

**(2) 「2系統の便」は一意に決まらない。**
同じ2系統でも運行区間が便ごとに違う（南口まで行く便、北口で終わる便、亥子谷止まりの便）。
2水準の便を指定するときは、系統番号だけでなく**起点・発車時刻・行先**まで書き切ること。

さらに、桃山台〜阪急南千里駅〜亥子谷の区間は **2・3・5・8・9・10・11 の7系統が重なる**。
とくに**3系統は2系統と起終点が同じ（南口⇔桃山台駅）で吹田側の経路だけが違う**ため、
乗り間違えるとデータ上で見分けがつきにくい。平日の桃山台発は 12:48〜16:24 が 2・2・3 の順で
3系統が混ざり、16:48以降は2系統が続く。**空いている便を15時台から選ぶときはここを外さないこと。**

### 検証しようがなかったもの

混雑そのものの時間帯別の記述は、**公式資料に人数・混雑の記載が一切ない**ため裏づけも反証もできない。
既知の制約（阪急バス・吹田市・豊中市とも系統別・便別の乗車人員は非公表）と整合する。
卒論で事実として引用することはできない。

> なお照合は4体のエージェントで走らせ、**2体がセッション上限で落ちた**
> （「吹田市民病院前」と「86系統」の担当）。結果的にどちらも別の経路（公式時刻表の
> 全停留所読み取りとバス停ページ）から答えが出たが、**専任の確認は取れていない**。

## 4.8 使う便を確定（公式時刻表の読み取り）

平日ダイヤを公式の路線別時刻一覧表から読み取った。PDFはテキスト層も埋め込み画像も持たない
完全なベクター描画だったので、400〜450dpiにレンダリングして目視で判読した。
既知の「桃山台17:18発→北口17:52→南口18:03」の列と一致することを検算に使い、
**2体のエージェントが独立に同じ値を読んでいる**（列のずれなし・判読不能ゼロ）。

### 確定した4便（集合・解散はどちらの日もＪＲ吹田駅（北口））

| | 便 | 起点 | 混雑 |
|---|---|---|---|
| **昼の日** 1本目 | 北口 **12:49発** → 桃山台 13:24着 | **北口始発・0人から** | 空いている |
| **昼の日** 2本目 | 桃山台 **13:48発** → 北口 14:22着 | **桃山台始発・0人から** | 空いている |
| **夕方の日** 1本目 | 北口 **16:20発** → 桃山台 16:55着 | **北口始発・0人から** | 中間（10〜22人） |
| **夕方の日** 2本目 | 桃山台 **17:18発** → 北口 17:52着 | **桃山台始発・0人から** | **実測39人** |

**4本すべてが始発便で、車内0人から積み上げられる。** 計数役の初期値カウントが不要になった。
北口始発は昼間の毎時 `:49` 発と 16:20／16:48／17:02／17:26／18:14／18:38／18:50 だけなので、
この条件を満たす組み合わせは多くない。

**混雑水準が3段階になった**（空いている／中間／数えきれない）。
RQ2の「どこで数えられなくなるか」の境目を見るのに、中間の1便は得になる。

### 経緯（判断の記録）

当初は1日で「空いている便」と「混んでいる便」の両方に乗る案（北口15:49発＋桃山台17:18発、
桃山台で54分待ち）を組んだ。待ちを縮めるため1本目を16:20発（10〜22人）に繰り下げる案を
Claudeが推したが、**松本から「それだと混んでいる時間帯になる。空いている状況下で
アプリがどう動くかを確かめるために空いている便を探している」と指摘があり、撤回した。**
空いている便の目的は「数えられるギリギリを探すこと」ではない。

そこで昼の日と夕方の日に分ける構成に戻した。集合場所は松本の指定でＪＲ吹田駅発着に統一。
その結果、夕方の日の1本目が16:20発（中間帯）になったが、これは
**空いている条件ではなく境目の観測**として位置づける。空いている条件は昼の日が担う。

### 3系統との取り違えに注意

桃山台〜阪急南千里駅〜亥子谷は 2・3・5・8・9・10・11 の7系統が重なる。
**昼の日の2本目は、毎時 `:24` 発が3系統**で、この系統は北口を通らない。絶対に乗せないこと。
北口発（両日とも1本目）は**3系統が北口を通らないので①のりばに並べば取り違えが起きない**。
17時以降の桃山台発には3系統の設定がない（この方向の3系統最終は16:24発）。

北口発の間隔は 17:26→17:50→18:14 が24分、19:02→19:38 が36分で、**昼間の12分間隔より粗い**。

ここは実測で確かめるしかない。**今回の設計は実測済みの17:18発を軸にしているので影響は受けない。**
