# 2026-10-05 認識合わせ ― ズレが3つ見つかった

実験当日までの準備を詰める前に、松本との認識を39項目の断定形で突き合わせた。
**「1行ずつ断定形で書き、違う番号だけ返してもらう」方式**が効いた。

## 1. なぜこの方式にしたか

きっかけは「回答する8か所」のズレ。`HANDOFF.md` には

> | 17 | 1便あたり指定停留所 | **8か所** | 松本 2026-09-24 |

としか書いていなかった。**合意しているように見えるが、誰が・どこで・何回答えるのかが書かれていない。**
松本は「全バス停で回答」のつもりで、こちらは「指定した8停留所だけで回答」と読んでいた。

**抽象的な合意語では表面化しない。当日の動作として断定形で書くと、違えば一目で分かる。**
以後、決定事項は「〇〇は8か所」ではなく「参加者は〇〇でだけ回答し、△△では回答しない」と書く。

## 2. 見つかったズレ

| # | 旧 | 新 |

| 28 | 指定した8停留所でだけ回答 | **全22停留所で回答** |

### 28 の影響

| | 8か所 | 全22停留所 |
|---|---|---|
| 回答数 | 384 | **1,056**（22×4便×12名） |
| 計数役の記録との対応 | 8/22 しか突き合わせられない | **1対1** |
| 回答の間隔 | 約5分に1回 | 約2分に1回 |

計数役は22停留所すべてを記録するので、**8か所だと基準値の14/22が突き合わせ相手なしになる。**
全停留所にしたことで ICC も全区間で測れる。

懸念は惰性（前と同じ数を考えずに入れる）だが、**連続して同じ値が続くかで検出でき、
それ自体がRQ2の指標になりえる。**

## 3. 決めたこと

### 3-1. 計数方法の比較は別日・専用実験にする

本実験（UI）と計数方法の実験を**切り離す**。

| | 本実験（UI） | 計数方法の実験 |
|---|---|---|
| 目的 | RQ1・RQ2・RQ3 | 足し引き vs 数え直し |
| 日程 | 10月中旬〜の8日 | **別日** |
| 参加者 | 12名 | **不要**（計数役だけ） |
| 計数役 | **2名**（足し引き） | **3名**（足し引き2＋数え直し1） |
| 記録 | 紙の記録用紙 | **乗降計測専用アプリ** |

**本実験の設計を汚さずに済む。** 計数方法の実験は参加者を集める必要がないので日程の自由度も高い。

判断の土台になった整理：

| 何のために | 正解データが要るか | 人数 |
|---|---|---|
| RQ1（どのUIが良いか） | **不要。**所要時間・操作量・欠損率は全部ログだけ | 0 |
| RQ2 のICC（同じ便の3人の一致度） | **不要。**参加者同士の比較だけ | 0 |
| RQ2 のクラス→人数の対応 | 要る。ただし**空いている便だけでいい**（混んだ便は元々参照値） | 2 |
| 計数方法の比較 | 要る | **3** |

### 3-2. 乗降計測専用アプリは紙の記録用紙を置き換える

併用ではない。計数役はアプリだけで記録する。

### 3-3. 事後アンケートを2枚に分ける

参加者の2日目は1日目から何週間も空くことがあり、まとめて最後に聞くと1日目の記憶が薄れる。

| 用紙 | いつ | 中身 |
|---|---|---|
| ①「今日の分」 | **各実施日の解散直後** | S1（1日目のみ）・S3（今日の回答行動）・S4（今日の1本目/2本目の比較） |
| ②「まとめ」 | **2日目の終わりだけ** | S2（2方式の比較）・S5（SUS）・S6（自由記述） |

**S4 が①側にあるのが肝。**「わからない」ボタンは同じ日の1本目と2本目で変わるので、
その日のうちに聞ける。日をまたぐと答えられない。
結果、**記憶に頼るのは S2（2方式の比較）だけ**になった。

副産物：**S3 が実施日ごとに取れるので、空いている日と混んでいる日を直接比べられる。**
旧版は 3-6 で「混雑時と空いているときで違ったか」を記憶から答えさせていた。
