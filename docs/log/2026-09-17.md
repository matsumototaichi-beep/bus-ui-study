## 2. 直したこと

### ヘッダーの折返し（`2ecb2f7` / `c21e2e2`）

`.navb` に `white-space:nowrap` が無く、管理者表示（「データ一覧」ボタンあり）で
ボタン文字が縦に折返してヘッダーが肥大していた。実測：

| | 修正前 | 修正後 |
|---|---|---|
| 375px・表示名が長い場合 | **120.8px** | 43.6px |
| 375px・「まつもと」 | 63.2px | 43.6px |
| 320px | 56.4px | 43.6px |

320×568 では `.center` が押し出されて**送信ボタンが画面外**に出ていた。

⚠️ `ADMIN_EMAILS` に `admin@id.local`（コメント：先輩/先方と共有する管理者アカウント）があり、
**先輩はこのアカウントで開く**。つまり先輩が「窮屈」と言った画面が、一番条件の悪い画面だった。
修正前に「直りました」と報告していたら、その場で反証されていた。

375px が 320px より悪かったのは、ブレークポイントが `max-width:360px` で
375/390px の実機に一切効いていなかったため。400px に広げた。
320px級では優先度の低いログイン名（`.sess`）を落としてナビに幅を譲る。

### 送信／スキップの下端固定（`2ecb2f7`）

uiStudy-0.4 で卒研側に入れていた `position:sticky; bottom:0` が本体に入っていなかった。
移植したことで、横向き（667×375・要スクロール164px）や SE1 の Safari 実効高
（320×460・79px）でも送信ボタンに常に届くようになった。

### 幽霊レコード（`2ecb2f7` / `c21e2e2`）

人数入力中にヘッダーの「報告」タブや「EN」を押すと `render()` → `renderMain()` が走るが、
`answering`/`pending` のガードが無かった。結果：

1. 入力中の値が消失（`n` は `renderCount` のローカル変数）
2. `answering=true` のまま取り残される
3. 次にクラスをタップすると `finalizeNow(true)` が発火し、`exact_count=null` の行が
   **画面ログに出ないまま** DB に入る（`submit()` を通らないので `logEntries` に行が無い）

`flushOutbox` と `finalizeNow` にはガードがあり、ここだけ漏れていた。
`answering` 中は `renderCount()` を描き直すようにし、入力途中の値は `pending` に持たせた。
「← 戻る」は従来どおり破棄（`cancelPick`）。

**卒研側は追加のガードが要った**（本体には不要）：

- `count_view_at` を描き直しで取り直さない。取り直すと `t_count`・`t_first` が
  リセットされ所要時間が短く出る。代わりに `screen_redraw` を記録して回数を残す
- テンキーの「プリセット未置換」フラグ（`fresh`）も保持。しないと描き直し後に
  プリセットが再び置換対象に戻る
- 条件（`variant`）はクラスタップ時に確定済みなので描き直しで進まないことを実測確認
  （`uistudy_seq_v1` / `uistudy_pseq_v1` とも不変）

### 版番号の表示（`2ecb2f7` / `c21e2e2`）

どの版を見ているか画面から分からず、修正済みかの確認で食い違う（キャッシュで旧版のまま、もある）。

## 4. 決定：ステップ幅を ±1/±5 に戻した（`phaseA-1.7` / `uiStudy-0.7.2`）

松本の判断。`−5 −1 [値] +1 +5` の4ボタンに変更（7列→5列）。

| | 320px | 375px | 390px |
|---|---|---|---|
| ±1/5/10（7列） | 35.3px | 41.7px | 43.1px |
| **±1/5（5列）** | **49.1px** | **58.8px** | **61.5px** |

**ただし解消はしていない。** ステッパー（横4ボタン）とテンキー（3×4グリッド）は
形が違うので完全には揃えられない。方法章に限界として書くほかに、
`screen_view` にボタン実寸（`ctl_w`/`ctl_h`）と画面サイズを記録して
解析で統制できるようにした。実測で `stepper: 58×50` / `numpad: 93×44` が
ログに乗ることを確認。

比較そのもの（±1/5 対 ±1/5/10）は本実験に第3要因として足せないので、
パイロットか代案2（室内版）で行う。これは先輩への相談事項として残る。
