# 指導教員への報告 文案（2026-09-25）

作成：2026-09-25 ／ 送信者：松本
方針：いただいた助言をどう反映したかと、**確定した実施内容**を述べる。
**誤りの指摘が目的ではない**ので、事実の食い違いは「確認した結果」として淡々と触れるにとどめる。
判断をお願いしたい点は最後に2つだけ置く。
実施の詳細は `docs/operation_plan.md` に集約してあり、この文案はその要約。

```
先日いただいた混雑の情報と、その前の「数えられる便をベースにする」というご助言について、
公式時刻表と照合したうえで設計を組み直し、使う便と環境を確定しましたので報告します。

■ ご助言をどう反映したか

「数えられる便をベースにする」という点が設計の骨格になりました。
空いている便で「どの回答UIが良いか」を測り、混んでいる便では正確な人数をあきらめて
「人数の代わりになる指標」を探す、という2本立てにしています。

方向によるピークの違いのご指摘も効きました。私たちが先行実験（9/18）で乗ったのは
桃山台駅→ＪＲ吹田駅（北口）の方向だけで、逆方向は測っていませんでした。

■ 混雑条件は、実測済みの便で足りていました

先行実験の実測では、桃山台駅17:18発の便で車内が8人から39人まで増え、
まさにその区間で目視が崩れています（私の記録に「正直この辺から車内人数は適当」と
残っています。逆算した実数とアプリの回答が最大10人ずれました）。

いただいた資料はこの便を「立ち客が出る程度で、すし詰めになることは滅多にない」と
評価しています。それはそのとおりです。ただ実験にとっては、その程度でもう正確な人数が
取れなくなります。すし詰めである必要はありませんでした。

■ 使う便（確定）

路線は吹田市内線2系統の1本だけ、区間も18停留所で同じにし、日と便で混雑水準だけを変えます。
集合・解散はどちらの日もＪＲ吹田駅（北口）です。
4便とも現行ダイヤ（2026年4月1日改正）に存在することを、停留所の時刻表で確認済みです。

  【昼の日】空いている
    1本目 ＪＲ吹田駅（北口）12:49発 → 桃山台駅 13:24着
    （折り返し24分）
    2本目 桃山台駅 13:48発 → ＪＲ吹田駅（北口）14:22着

  【夕方の日】混んでいる
    1本目 ＪＲ吹田駅（北口）16:20発 → 桃山台駅 16:55着   … 中間（10〜22人の見込み）
    （折り返し23分）
    2本目 桃山台駅 17:18発 → ＪＲ吹田駅（北口）17:52着   … 先行実験の実測で8人→39人

この4便を選んだ理由は3つあります。

第一に、4本すべてが始発便で、車内0人から積み上げられます。北口を始発とする便は
昼間の毎時49分発と、16:20／16:48／17:02／17:26／18:14／18:38／18:50 に限られるので、
この条件を満たす組み合わせは多くありません。計数役の初期値カウントが不要になります。

第二に、集合も解散もＪＲ吹田駅なので、参加者が大学からそのまま来られます。

第三に、混雑の水準が3段階になります。空いている（昼）、中間（16:20発）、
数えきれない（17:18発）。RQ2で「どこで数えられなくなるか」の境目を見たいので、
中間の1便があるのはむしろ得になります。

停留所は両方向とも18で、順序も完全に対称であることを公式時刻表で確認しました。

  ＪＲ吹田駅（北口）→ 片山小学校前 → 朝日が丘町名神下 → 上山手町 → 佐井寺南が丘 →
  総合運動場前 → 竹谷 → 佐井寺 → 佐井寺北 → 五月が丘 → 亥子谷 → 佐竹台六丁目 →
  佐竹台五丁目 → 高野台中学校前 → 佐竹台診療所前 → 阪急南千里駅 → 桃山台二丁目 → 桃山台駅

片道34〜35分です。

    16:10  ①のりばへ移動。停車中の車内で練習2回
    16:20  1本目 発車          ← 私はここで離脱します

    17:18  2本目 発車

私は同乗しません。回答の中心指標が「『わからない』ボタンを押すかどうか」なので、
発案者が同じバスに乗って見ていると、本当は分からないのに適当な数を入れてしまう
――測定したい現象そのものが観察者の存在で歪みます（要求特性）。
送り出しで離脱し、便の記録は計数役2名に兼ねてもらいます。

■ 日程

使える平日は16日です（10/12 スポーツの日、11/3 文化の日を除く）。

  10/13（火）・14（水）・15（木）・16（金）・19（月）・20（火）・23（金）
  11/2（月）・4（水）・5（木）・6（金）・9（月）・10（火）・11（水）・12（木）・13（金）

実施は4日なので、予備が12日残ります。雨・欠席・遅延は十分に吸収できます。

土日は使いません。この4便が土休日ダイヤに存在しないためです（北口16時台は17/33/48で
16:20が無く、桃山台17時台は北10/20/北40/50で17:18が無い）。便を選び直すと
平日データと混ぜられなくなるので、予備日からも外しています。

どの日を昼にしてどの日を夕方にするかは、参加者の都合に合わせて決めます。
同じ方に昼と夕方の両方へ来ていただければ、混雑水準が同じ人の中で比べられるので
そちらが望ましいのですが、片方だけの方がいても成立するようにしてあります。

1便あたりの参加者は3名に抑えます（団体に見えないため）。合計12名です。

■ 公式資料と照合して分かったこと

いただいた情報の事実部分を、阪急バス公式（運行系統図・運行系統一覧・路線別時刻一覧表・
バス停ページ）と照合しました。時刻表はテキストを持たない画像のPDFだったので、
画像として描画して読み取り、既知の「桃山台17:18発→北口17:52→南口18:03」の列と
一致することを検算に使っています。

・北口と南口で発着する系統の構成が違うのは、ご指摘のとおりでした。
  北口は8系統（2・4・5・6・13・19・20・21）ですべて吹田市内線、南口は12系統で、
  摂津方面（30・31）・園田方面（24）・曽根方面（86）が加わります。

・ただし、この違いは2系統の便ごとの混雑差の根拠にはなりませんでした。
  2系統は「南口〜吹田市役所前〜北口〜上山手町〜…〜桃山台駅」という一本の系統で、
  北口と南口の両方に停まります。北口グループ対南口グループの比較として使うと、
  それは2系統以外（北口のみ＝5・6・21／南口のみ＝3・10・12ほか）の話になってしまいます。

・実測便の裏づけが取れました。桃山台駅17:18発は、公式時刻表と停留所名・順序・
  所要時間まで一致します。なおこの便は北口止まりではなく南口18:03まで行く便でした
  （私が北口で降りただけです）。参加者には北口で降りるよう念を押します。

・なお「吹田市民病院前」は、2系統の経路上には見当たりませんでした。

■ 時刻表を見て気になった点

「平日17:30〜19:30が最大のピーク」というご指摘に対して、ダイヤがそう読めませんでした。
北口発の間隔は 17:26→17:50→18:14 が24分、19:02→19:38 が36分で、昼間の12分間隔より
むしろ粗くなっています。19時台は2本だけで、どちらも南口からの通し便です。

本当にピークなら増発しているはずなので、ここは実際に乗って確かめるしかないと考えています。
今回の設計は実測済みの17:18発を軸にしているので、この点が外れても影響は受けません。

■ 乗り間違いへの対策

桃山台駅〜阪急南千里駅〜亥子谷の区間は 2・3・5・8・9・10・11 の7系統が重なります。
とくに3系統は2系統と起終点が同じで吹田側の経路だけが違うため、
乗り間違えるとデータ上で見分けがつきません。

北口発（両日とも1本目）は①のりばに並べば済みます。3系統は北口を通らないので、
構造的に取り違えが起きません。

桃山台発（両日とも2本目）が要注意です。桃山台駅2番のりばには
[2][3][5][8][9][10][11][61][62][65][69] が集中しているうえ、
使う[2]の行先表示は「ＪＲ吹田駅（南口）」で、「ＪＲ吹田駅（北口）」と出て発車するのは
[5]という別系統です。「北口ゆき」を探すと[5]に乗ってしまうので、
「[2] ＪＲ吹田駅（南口）ゆきに乗り、北口で降りる」と手順に明記します。
とくに昼は毎時24分発が3系統で北口を通らないので、ここも外さないようにします。

■ 混雑の公開データは存在しませんでした

系統別・便別の乗車人員は、阪急バス・吹田市・豊中市のいずれも公表していませんでした。
吹田市統計書は事業者単位の年間値まで、豊中市統計書はバス停単位で主要10停留所までです。

したがって「どの便がどれくらい混むか」は、実際に乗って数えるしかありません。
現時点で数字があるのは9/18に私が乗った1便だけです。
本実験では計数役2名（前扉・後扉）を置いて基準値を作ります。
選んだ4便はすべて始発なので、車内0人から積み上げられます。

■ 研究の組み直し

ご助言を受けて、問いを3本立てにしました。

RQ1（空いている便）数えられる状況で、どの回答UIが良いか
  → 入力方式（ステッパー／テンキー）と「わからない」ボタンの有無の2×2

RQ2（混んでいる便）正確な人数の代わりになる指標は何か
  → 第一候補は、すでにアプリにある「混雑度6段階のクラス」そのもの

RQ3 空いている便で作った「指標→人数」の関係は、混んでいる便に外挿できるか

位置づけは「移動中のバス車内で正確な乗車人数は測れない。しかし混んでいるかどうかは
取れる。そして混雑時には人数の代わりになる手がかりがある」としました。

クラスを第一候補にしたのは、アプリの改修が要らず、1タップで答えられるので
混雑時にも欠損しにくいからです。検証の要になるのは
「混雑時にクラスの一致度（同じ便に乗った複数名の回答が揃うか）が落ちるかどうか」です。
人数が混雑時に崩れることは分かっていますが、クラスの一致度まで崩れるなら
「混んでいるかどうかも取れない」ことになり、この位置づけ自体が成立しません。
反証されうる形にしてあります。

なお混雑度は、これまで「統制できないので事後に層別する変数」として扱っていましたが、
日と便で水準を作れるようになったので、操作する要因に格上げしました。

■ ご判断いただきたい点

① 使う便の選定でよいか

   4便とも現行ダイヤ（2026年4月1日改正）に存在することは、停留所の時刻表で確認しました。
   ただし車内がどれくらい混むかは、実測があるのは桃山台17:18発の1便だけです。
   系統別・便別の乗車人員はどの機関も公表していないので、
   とくに昼の便が本当に空いているかは、乗ってみないと分かりません。

② 参加者の交通費の手続き

   総額は1万3千〜1万5千円程度の見込みです。大学から出るものと思っていますが、
   どの費目で、謝金扱いか実費精算か、証憑は何が要るか、事前申請が要るかが
   分かっていません。事務へ確認する際の窓口と進め方をご教示いただけると助かります。

進捗としては、アプリは実装と動作確認を終えて公開済み、事後アンケートの設計、
計数役の記録用紙（両方向とも停留所名を入れた印刷用）まで用意できています。
残るのは条件割当表の作成と、参加者の都合に合わせた日程の確定です。
```
