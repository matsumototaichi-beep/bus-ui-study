- **2段階の回答**：クラス（6段階）を1タップ → 人数画面（任意）。人数・バス停・位置情報はすべて任意（**強制しない**のがユーザー方針）
- **4条件のローテーション**：`UI_CONDS = [stepper/none, numpad/median, stepper/median, numpad/none]`。1回答ごとに次の条件へ
  - 開始位置は**実験バーの「参加者」番号**で決まる（`(番号-1) mod 4`）。同じ便の参加者1〜4が**同じ瞬間に必ず別々の条件**になる＝計画書 §3.1 のラテン方格
  - 参加者番号を変えると**試行カウンタ `seq` が 0 に戻る**（前の参加者の回数が「何回目の回答か」に混ざらないように）
  - 未設定なら従来どおり端末ごとのランダム開始（下見・単独テスト用）。どちらで決まったかは `variant.offset_src`（`participant` / `random`）に残る
- **練習モード**（`uiStudy-0.7`）：実験バーの「練習」トグル。オン中は画面上部に橙のバナーが出て、タップで終了できる
  - オン中の回答は `practice: true` で記録（操作ログ側 `context.practice` と回答側 `ui_responses.practice` の両方）。分析では `practice = false` で絞る
  - **練習は専用カウンタ（`uistudy_pseq_v1`）を使い、本番の条件の順番を進めない**。練習回数が人によって違っても本番の割当がずれない
  - 実験コード・参加者番号と同じく日付で失効。参加者番号を変えると練習カウンタも 0 に戻る
  - ⚠️ **何回練習するか（そもそも入れるか）は未定**
- **初期値**：`none`＝`—`（破線枠）／`median`＝選んだクラスの目安範囲の中央値をプリセット
- **テンキー**：プリセットは最初の数字キーで置換、以降は追記。2桁上限（3桁目は無視して枠を一瞬光らせる、`ignored:true` で記録）。`C`＝全消去、`⌫`＝1桁削除
- **報告画面上部の実験バー**：実験コード（英数字とハイフン・8文字まで）、着席／立席トグル。未設定は橙色
- **送信／スキップはスクロール領域の下端に固定**（テンキー条件だけ送信ボタンが画面外になり到達コストが変わるのを防ぐ）
- **ログ**：1回答＝1セッション。`dt`＝セッション開始からの相対 ms（端末時計のズレ対策）。イベント・所要時間・タップ数・訂正回数を記録。仕様は `UI_STUDY_SPEC.md` §6
- **保存先**：いまは**端末の localStorage のみ**。Supabase のテーブルが未作成なので送信は失敗する（＝NAIST 側のデータは汚れない安全側）
- **データ分離**：Supabase のプロジェクトは NAIST アプリと同じだが、テーブルは `ui_responses` / `ui_sessions` と別。**NAIST の `responses` テーブルには触らない**

- **進め方**：詰まったら教授に質問 or コミットして GitHub で共有。会話が長くなったら教授が要約。**AIの調査は本文PDFを読ませる**
